## Running the Python tests

Install once: `python -m pip install -r tests/python/requirements.txt` (the same packages as `python/requirements.txt`).

- Generator unit tests: `python -m pytest tests/python/test_master_data_generator.py -q`, `python -m pytest tests/python/test_opening_inventory.py -q` and `python -m pytest tests/python/test_transactions.py -q` (no database).
- Seeder database tests: set `NORDICCART_DB_TESTS=1`, then `python -m pytest tests/python/test_master_data_seed_db.py -v`. They create databases named `nordiccart_seed_test_*`, apply V001 to V007 and drop them; they never connect to `nordiccart_oltp`. Without the variable they are skipped.
- Opening inventory database tests: with the same variable, `python -m pytest tests/python/test_opening_inventory_db.py -v`. They use databases named `nordiccart_inventory_test_*` (V001 to V007 plus the master pilot) and drop them; they never connect to `nordiccart_oltp`.
- Transaction database tests: with the same variable, `python -m pytest tests/python/test_transactions_db.py -v`. They use databases named `nordiccart_tx_test_*` (V001 to V007, the master pilot and the opening inventory) and drop them; they never connect to `nordiccart_oltp`.
- Replenishment tests: `python -m pytest tests/python/test_replenishment.py -q` (no database) and, with the same variable, `python -m pytest tests/python/test_replenishment_db.py -v`. The database tests use databases named `nordiccart_repl_test_*` (V001 to V007, the master pilot, the opening inventory and the 20 pilot orders) and drop them; they never connect to `nordiccart_oltp`.
- Demand model tests (Phase 3 step 5, S2), no database: `python -m pytest tests/python/test_demand.py -q` and `python -m pytest tests/python/test_demand_calibration.py -q` (full profile, seeds 1 to 5, about one minute). The calibration report figures come from `python python/run_demand_calibration.py`.
- Pilot scope tests (Phase 3 step 5, S1): `python -m pytest tests/python/test_pilot_scope.py -q` (no database) and, with the same variable, `python -m pytest tests/python/test_pilot_scope_db.py -v`. The database tests use databases named `nordiccart_s1_test_*` (V001 to V007, the master pilot, the opening inventory and both pilots) and drop them; they never connect to `nordiccart_oltp`.
- V009 tests (Phase 3 step 5, S4), **disposable server only**: with the same variable, `python -m pytest tests/python/test_v009_db.py -v`. They use databases named `nordiccart_v009_test_*` and drop them; never `nordiccart_oltp`. Deployment: `docs/phase3_v009_deployment_and_rollback_guide.md`.
- V008 security tests (Phase 3 step 5, S3), **disposable server only** (V008 creates cluster roles `nordiccart_*`; logging in as them needs an authentication method without a password, such as the sandbox's trust): with the same variable, `python -m pytest tests/python/test_v008_security_db.py -v`. They use databases named `nordiccart_v008_test_*` and drop them; they never connect to `nordiccart_oltp`. Deployment to the real database: `docs/phase3_v008_deployment_and_rollback_guide.md`.

The database tests read the server from the PG variables first and fill missing ones from `config/.env`. To run them against a disposable server instead of your own, set all of `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD` and `PGDATABASE` in the terminal first (see `docs/phase3_replenishment_guide.md`, Part 4).

Step-by-step commands for Windows and VS Code: `docs/phase3_master_data_generator_guide.md`, `docs/phase3_opening_inventory_guide.md`, `docs/phase3_transactions_guide.md` and `docs/phase3_replenishment_guide.md`.

## Running the Python concurrency test

`tests/python/test_v007_concurrency.py` creates its own database `nordiccart_concurrency_test`, applies `database/migrations/V001` to `V007` to it, runs the 14 scenarios and drops it. It never connects to `nordiccart_oltp` and refuses any other database name. If the test database already exists (an interrupted run) it stops unless you pass `--recreate`; `--keep` leaves it in place for inspection.

Requirements: Python 3.10 or later, `pip install -r tests/python/requirements.txt` (psycopg 3), and a role that can create databases. Connection settings come from the standard variables `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD` (see `config/.env.example`). Exit code 0 means every scenario passed. Step-by-step commands for Windows: guide Part C, step C5.

Since S3: `--through 8` also applies V008 to the test database, and `--through 8 --role nordiccart_loader` runs the fixtures and every scenario session as that login (migrations still run as the connecting superuser). Since S4: `--through 9` also applies V009. Without these options the test behaves as before (V001 to V007, connecting role). `--through 8` and `--through 9` are for a disposable server only (cluster roles).
